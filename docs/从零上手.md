# 从零上手：第一次使用与教学演练

这份教程面向第一次拿到工具包的朋友。完成后，你应能确认 skill 已被读取、各端是否连通，以及如何启动并关闭一个两轮工作包。

本仓库提供流程规范、skill 与模板；Grok BOT、秘书Bot、中转助手和 dots 需要使用者自行具备相应运行环境。这里的名称是原流程中的角色称呼；本仓库没有它们的安装包、服务地址或通用 API 适配器，也没有验证过跨环境的一键部署。缺少这些工具时，可先学习和手动演练；全自动多轮中转要等连接能力准备好。

## 1. 取得工具包

仓库目前是私有的。请仓库所有者邀请你的 GitHub 账号成为协作者，接受邀请后访问仓库。也可以由所有者把不含私人配置的工具包文件发给你。

能访问仓库后，在 GitHub 的 Code 菜单选择 Download ZIP 并解压，或在已配置 GitHub 登录的终端执行：

```sh
git clone https://github.com/michael20050413-bot/chatgpt-grokbot-codex-workflow.git
cd chatgpt-grokbot-codex-workflow
```

验收：能打开根目录 README.md、`skills/relay-research-review/SKILL.md` 和 [启动模板](../templates/新项目启动模板.md)。

## 2. 让 Codex 先带你配置

在你的 Codex 中打开工具包目录，复制下面这段话。即使还未安装 skill，也能先让 Codex 直接读取文件。

```text
请阅读当前工具包的 README.md、docs/从零上手.md 和 skills/relay-research-review/SKILL.md，带我完成首次配置。先说明你实际能使用哪些工具；检查 skill 安装位置并在不覆盖已有版本的前提下安装或指导安装，然后验证是否能发现。再逐项检查原 ChatGPT 对话读取、秘书Bot/中转助手通信、dots 操作 Codex、实际文件回传、目标消息查询和定时检查权限。不要把读过规则当作连接成功。能独立完成的继续做，确实缺少配置时再问我；不要向我索取密码、令牌或验证码，由我在官方界面完成登录。未经授权不要发送测试消息或创建定时任务。最后给出已证实、未知、缺失三类结果，并告诉我下一步该填启动模板的哪几项。先不启动真实项目。
```

这段提示词用于首次引导，不代表已经完成安装或连通验收。你应看到 Codex 给出实际文件位置和能力缺口，而非一句“配置完成”。

## 3. 安装与验证 skill

如果已由 Codex 完成安装，不必再复制一次。手动安装时，复制整个 `relay-research-review` 文件夹，保持 `SKILL.md` 层级。

当前官方文档列出的 Codex 用户级位置为 `~/.agents/skills/`，项目级位置为 `.agents/skills/`。本工具包最初按原环境的 `~/.codex/skills/` 发布；已有环境可能使用该位置。新用户先使用官方位置并验证发现结果，不要向多个位置重复安装。依据：[官方 CLI 安装文档](https://developers.openai.com/api/reference/cli)。核对日期：2026-11-10。

macOS / Linux，在工具包根目录运行（Python 3 可用时）：

```sh
python3 - <<'PY'
from pathlib import Path
import shutil
source = Path('skills/relay-research-review')
target = Path.home() / '.agents/skills/relay-research-review'
if not (source / 'SKILL.md').is_file():
    raise SystemExit('请在工具包根目录运行')
if target.exists():
    raise SystemExit('目标已存在，请先比较并合并，未覆盖')
target.parent.mkdir(parents=True, exist_ok=True)
shutil.copytree(source, target)
print('已复制 skill；接下来在 Codex 中验证是否发现')
PY
```

Windows 用户也可通过文件管理器把整个文件夹复制到用户主目录下的 `.agents/skills/`，目标已有同名文件夹时先比较。容器或远程 Codex 必须安装到它实际运行的环境，宿主机复制成功不代表远端可读。

重新打开会话或按客户端提供的方式刷新技能后，发送：

```text
请使用 $relay-research-review，先说明你读到的技能规则与实际文件位置，并列出当前项目缺少的绑定。只检查，不发送消息、不启动任务。
```

验收：Codex 能读取对应 skill，并说明四种交接动作和具体缺少的绑定。若未发现，先让它直接读取完整 SKILL.md 临时使用，同时排查安装位置和客户端支持；直接读文件只证明规则可读，不能证明已自动发现。

## 4. 检查完整流程的连接条件

由首次引导助手协助检查以下能力。先做只读预检；真实发送或调度测试应明确限定在你授权的测试工作包中。未知值写“未知”。

|检查项|需要看到的结果|
|---|---|
|原 ChatGPT|中转助手能读取指定原对话的完整回复和材料，并能回传到同一对话|
|秘书Bot 与中转助手|角色在你的工具环境中真实存在，项目绑定可读回，主对话能收到进展|
|dots 与 Codex|能定位你的工作区和任务 ID，操作不会落到别的项目|
|文件回传|中转助手能取得实际文件，原 ChatGPT 能打开对应版本|
|目标端查询|断线后能查已收消息或内容证据，不能仅查询本地发送标志|
|定时检查|有权限的 Grok BOT 能创建、读回实际间隔与启用状态，并停用任务|

没有 Grok BOT 或 dots 时，先取得你所使用服务的配置说明和访问能力；本仓库不能仅凭角色名创建这些服务。也可以先手动转交任务书与文件，练习同一协议，但这属于手动演练，不能称为自动流程已跑通。

## 5. 填项目卡并启动

打开 [新项目启动模板](../templates/新项目启动模板.md)，只填四项：项目名称、目标对话、Codex 工作区、授权范围。真实对话与路径仅保存在你自己的私人项目。

先把模板第一段及项目卡发给原 ChatGPT，和它确定目标与大纲，等完整首轮任务书生成结束。再把第二段及同一项目卡发给秘书Bot，第一句就是“启动这个工作包。”。后续由中转助手自动取完整指令。

首次启动应看到绑定的读回结果，以及检查任务的实际 ID、间隔和启用状态。没有证据就不能当作已配置。

## 6. 用两轮小练习验收

建议先用虚构项目“晨光资料索引”，只授权在独立测试工作区编辑 `index.md`、在已绑定测试对话间传递任务书和实际文件，以及设置和停用本测试包检查；不包含发布或修改其他项目。先与原 ChatGPT 约定这是教学演练：第 1 轮审阅后安排一项真实的小修改，第 2 轮符合验收后完成。参考 [完整示例](../examples/两轮交接.md)。

1. 首轮生成两条虚构资料索引，Codex 交付实际 `index.md`。秘书Bot 主对话应报告“第 1 轮已送审”。
2. ChatGPT 读到文件后，用“继续”交接块要求调整分类，并附完整第 2 轮任务书。确认秘书Bot 报“下一轮已送到 dots”，你不需要手动复制第二轮指令。
3. 第 2 轮文件通过审阅后，ChatGPT 用“完成”交接块列出回执。秘书Bot 报最终文件版本，并读回检查任务已停用；不应出现第 3 轮。
4. 若有安全测试条件，在目标已收到测试指令、本地尚未记录回执时模拟连接中断。恢复后应先查目标端，补记接收证据，不能再次发送相同指令。不要为了演练中断正在执行的真实项目。

在私人项目保留消息定位、文件版本、三组模型值、审阅块及停检证据。没有真实连接条件时，只运行 `python3 scripts/validate.py` 可检查本地示例；它通过不代表以上实操已通过。

## 7. 常见卡点

|现象|下一步|
|---|---|
|朋友打开仓库是 404|确认已接受私有仓库协作者邀请，或使用所有者提供的工具包|
|安装后找不到 skill|核对 Codex 实际运行环境和技能位置，检查文件夹层级，重新打开会话；可先直接读取 SKILL.md|
|Bot 不认识秘书Bot/dots|这些是角色称呼，先配置对应服务、助手和权限；仅安装 skill 无法补齐|
|原 ChatGPT 拿不到文件|检查实际附件是否到达及是否可打开，回报待材料，不用摘要代替审阅|
|没有可读的模型运行证据|写“未知”，保留请求值与可设置值，不能据此声称实际运行配置|
|断线后不知道是否收到|查询目标端；仍无法核实就暂停该发送并报告卡点|
|输入框里有用户草稿|保留草稿，不覆盖或代发；无法安全操作则报告|
|完成后仍有定时检查|核对本工作包调度 ID 并停用、读回；未成功就报告，不能声称已收尾|

完成首次实操后，新项目通常只需复用启动模板。完整规则见 [skill](../skills/relay-research-review/SKILL.md)，已验证范围见 [验证记录](../VALIDATION.md)。
